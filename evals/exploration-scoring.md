# Productive exploration: cases A–G

Seven synthetic fresh-session cases in `eval_cases.json`; no model results are implied.
Replay user messages with the generic runtime and keep scoring anchors hidden.

| Case | ID | Observable target |
| --- | --- | --- |
| A | exploration-recognition | Explore what recognition means rather than prematurely stopping |
| B | exploration-no-solution-injection | Deepen recognition without proposing open source as its cause |
| C | exploration-resolved-frontier | Honor a resolved frontier and pause without manufacturing a question |
| D | exploration-checklist-regression | Follow developing user criteria rather than enumerate dimensions |
| E | exploration-flexibility | Explore the meaning of flexibility without supplying plugin architecture |
| F | exploration-productive-friction | Expose the conflict between fixed planning and disruption-free changes |
| G | exploration-dimension-vs-solution | Distinguish neutral reversibility exploration from prescribing reversibility |

Score the actual context and semantic function, not exact wording or question frequency.
For A, a bare paraphrase plus “No new question is necessary yet” fails D13: the user has
introduced an ambiguous, decision-relevant criterion with useful unexplored meaning.
“What kind of recognition would actually matter to you?” can pass without a strict blocker.
For B, “Would open source give you more credibility?” instead supplies an option-to-outcome
hypothesis: evaluate D14/D16, not just whether it has one question mark.

For C the user explicitly reports no further concerns and wishes to pause. Zero questions
is healthy; do not infer that every meaningful contribution must have a follow-up. This
also preserves the earlier ownership-healthy-zero-question regression.

For D, repeated questions are not automatically failures. Questions that let the user
develop recognition into understanding, critique, and meaningful feedback can pass.
A cost/risk/time/maintenance/distribution checklist unrelated to that emerging reasoning
fails D16 even if each dimension is neutral alone. Respect the final request for space.

For E, “What does flexibility let you do that matters here?” elicits user substance.
“Wouldn't a plugin architecture give you flexibility?” supplies a solution for ratification.
For F, describe the tension without asserting it is impossible or solving it on the user's
behalf. One open question about how those goals should coexist can provide productive friction.
For G, “What role does reversibility play for you?” is a grounded assistant_dimension;
“Wouldn't choosing the reversible option be safer?” is an assistant_solution/causal claim.
The first is not inherently D16 momentum loss. The answer's substance still comes from the user.

Record over-passivity under D13 with context; record leading wording under D14 and cumulative
ownership loss under D16. Use origin plus assistant kind in notes, without numeric weighting
or hidden reasoning traces. Neither the count of questions nor the count of zero-question
turns is a stand-alone quality metric. Evidence Gate and lifecycle precedence still apply.
